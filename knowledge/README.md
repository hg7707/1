# 知识库填写说明

这个目录现在按 7 类维护。每个文件都是 JSON 数组，新增知识时把对象追加到对应文件里。

## 文件分类

- `ninja_basics.json`：忍者基础介绍，例如技能机制、资源特性、容易误解的效果。
- `ninja_playstyles.json`：忍者基础打法思路，例如强势距离、起手方式、弱点、资源规划。
- `ninja_tips.json`：忍者使用技巧，例如骗替点、细节操作、连段中的取舍。
- `duel_logic.json`：决斗场底层逻辑，例如走位、替身、骗替身、压场、奥义确认、防守资源。
- `matchup_decisions.json`：具体对局的优秀决策，例如 A 打 B 的关键距离、资源交换和劣势处理。
- `matchmaking.json`：决斗场匹配机制和冲分策略。版本相关、经验向内容必须标低置信度和需要验证。
- `rank_recommendations.json`：上分忍者推荐，按不同分段维护。

## 通用格式

```json
{
  "id": "唯一编号",
  "title": "条目标题",
  "level": "beginner/intermediate/advanced",
  "tags": ["玩家可能会说的关键词"],
  "summary": "忍者或对局类可用 summary",
  "content": "机制、误区、训练类可用 content"
}
```

## 写法要求

- 一条知识只讲一个判断点。
- `tags` 要放玩家会输入的词，比如“空技能”“骗替”“压墙角”“开大”。
- 具体技能、霸体、无敌、抓取、扫地、冷却、版本强度，必须确认后再写。
- 不确定或版本相关内容，不要写成确定规则，要写“可能”“需要验证”“基于样本观察”。
- 带 `"template": true` 的条目只是模板，不会进入检索；复制模板后要删除这一行。

## 入库后检查

每次新增或修改后运行：

```powershell
npm run check
```
